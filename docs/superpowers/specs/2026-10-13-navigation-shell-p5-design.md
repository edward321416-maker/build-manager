# 하단 탭바·왼쪽 메뉴 (P5) 설계

- 날짜: 2026-10-13. 작성: Claude Opus 5.5 (Claude Code).
- 위험 등급: 고위험(DEV-01, DEV-04).
  - 인수 때 고정한 화면 배치(FROZEN)를 바꾼다. [인수인계](../../../ops/CHAT_HANDOFF.md)에 "RC1 functional contracts and the accepted Apple/Toss/spatial/responsive UI remain frozen"이라고 적혀 있다.
  - 로그인 뒤 소속 선택과 로그아웃 자리를 옮긴다.
  - API, DB, 권한, 서버 판단은 바꾸지 않는다.
- 근거
  - [메뉴 점검](../../../research/ux/2026-10-10-menu-audit.md) 9.2절의 탭 구성과 P5(메뉴 뼈대).
  - [내비게이션 규칙 설계](2026-10-10-navigation-rules-design.md)의 D1–D8.
  - [디자인 규칙](../../../design/DESIGN_RULES.md) 8.10, 8.13–8.16, 12, 13절과 16절의 내비게이션 항목.
- 범위: 웹 `/core`만. 모바일 앱의 탭바는 앱 v2 때 만든다.

## 문제 (main `7256df7`에서 코드로 확인함)

1. `/core`는 1023px 이하에서 위쪽 메뉴를 쓴다. 규칙은 767px 이하 하단 탭바, 768px 이상 왼쪽 메뉴 248px이다(8.10, 8.14).
2. 메뉴가 두 군데로 나뉘어 있다.
   - 위쪽 `작업 이동`에는 `접수`(관리자는 `업무함`)와 `입주 연결` 두 항목만 있다(`login-screen.tsx`).
   - 관리자의 `업무함 / 호실 정비 이력` 전환 버튼은 화면 안의 `관리자 보기`에 따로 있다(`core-screen.tsx`).
3. 소속 선택과 로그아웃이 1차 메뉴 위에 늘 보인다. 규칙은 이 둘을 계정 메뉴('내 정보')에 둔다(8.10, 8.16).
4. 2026-10-12 결정으로, 휴대폰 위쪽 메뉴 링크만 높이 40px이다(규칙 맨 위 [DECISION], 16절, `core-design.module.css` 767px 이하 규칙, `scripts/design-audit.mjs`의 `phoneMenu`). 탭바가 생기면 지우기로 했다.
5. 처리할 일을 한곳에서 볼 수 없다.
   - 세입자의 '내 답변 필요'는 목록 행 표시로만 보인다. 방문 시간 선택과 결과 확인은 요청을 열어야 안다.
   - 관리자의 결정 필요, 긴급 확인, 답변 대기, 기한 지남은 업무함 행과 정렬로만 드러난다.
6. Tabler 아이콘이 아직 없다. 뒤로 버튼은 글자 `← 목록으로`다.

## 목표

- 역할마다 메뉴 정의 한 벌로 767px 이하의 하단 탭바와 768px 이상의 왼쪽 메뉴를 함께 그린다. 그래서 항목, 순서, 이름, 아이콘이 늘 같다.
- 탭 '알림'에 처리할 일을 모으고, 건수를 배지로 보인다. 새 서버 기능 없이 이미 있는 응답으로 만든다.
- 휴대폰 40px 예외를 없앤다.
- 개발 접근 코드 모드(B1이 아닌 `/core`)에도 같은 메뉴를 붙인다.

## 범위 밖

- 모바일 앱(Expo)의 탭바와 안전 영역(앱 v2).
- 실제 알림 기능: 받은 기록, 읽음 상태, 푸시, 알림 설정.
- 아직 내용이 없는 계정 메뉴 행: 도움말·문의, 약관·개인정보 처리방침, 알림 설정. 빈 행은 두지 않는다.
- `/workspace` 화면의 디자인 이전. 이번에는 링크만 건다.
- 요청 상세를 주소로 바로 여는 기능(상세 딥 링크).

## 설계

### 1. 메뉴 한 벌

메뉴 정의는 순수 데이터 한 곳(`nav-config.ts`)에 둔다. 탭바, 왼쪽 메뉴, '더 보기' 목록, '내 정보' 목록, 주소 검사가 모두 이 정의만 읽는다.

세입자(`TENANT`)

| 순서 | 주소 `tab` | 라벨 | 아이콘 |
| --- | --- | --- | --- |
| 1 | `home` | 우리 집 | `home` |
| 2 | `requests` | 내 요청 | `clipboard-list` |
| 3 | `alerts` | 알림 | `bell` |
| 4 | `me` | 내 정보 | `user` |

관리자(`ORG_ADMIN`, `PROPERTY_STAFF`)

| 순서 | 주소 `tab` | 라벨 | 아이콘 |
| --- | --- | --- | --- |
| 1 | `work` | 업무함 | `clipboard-list` |
| 2 | `alerts` | 알림 | `bell` |
| 3 | `more` | 더 보기 | `dots` |

- 라벨은 모두 공백 포함 4자 이내다(8.14). '홈' 뜻의 탭이 맨 왼쪽이다.
- 세입자의 '내 정보'는 맨 오른쪽 탭이다. 관리자는 '더 보기'가 있어 '내 정보'가 그 목록 맨 아래다(8.14).
- 역할은 서버가 준 값만 쓴다. B1에서는 고른 소속의 역할(`CoreAccessDto.organizations[].role`), 개발 모드에서는 세션의 역할이다.

'더 보기' 목록(관리자). 주소는 `?tab=more&view=<값>`이다.

| 순서 | 행 | `view` | 보이는 역할 |
| --- | --- | --- | --- |
| 1 | 호실 정비 이력 | `maintenance` | 모든 관리자 |
| 2 | 입주 연결 | `invitations` | `ORG_ADMIN` |
| 3 | 건물·호실 관리 | 없음. `/workspace`로 이동 | `ORG_ADMIN`, B1 모드 |
| 4 | 내 정보 | `me` | 모든 관리자 |

- `/workspace`는 B1 모드에서만 열리고(그 밖에는 404), 아직 옛 디자인이다. PR 1에서 체험 세션으로 열리는지 확인한다. 열리지 않으면 체험 세션에서는 이 행을 빼고, PR에 이유를 적는다.

'내 정보' 목록(계정 메뉴, 8.16). 위에서부터 이 순서다.

| 행 | 세입자 | 관리자 | 개발 모드 |
| --- | --- | --- | --- |
| 내 호실(건물과 호실 이름) | `view=units` | 없음 | 세입자만 |
| 내 소속(바꾸기) | 화면 안 선택 상자 | 화면 안 선택 상자 | 없음 |
| 호실 연결(지금의 세입자 '입주 연결') | `view=link` | 없음 | 없음 |
| 오픈소스 라이선스 | `view=licenses` | `view=licenses` | 있음 |
| 로그아웃(맨 아래) | 버튼 | 버튼 | 버튼 |

- 내 소속은 지금의 선택 상자(`내 소속`, 긴 이름을 줄바꿈해 보이는 `.core-org-current` 포함)를 그대로 옮긴다. 소속이 하나면 이름만 글자로 보인다.
- 소속과 호실 연결은 B1 기능이라 개발 모드에는 없다.
- 관리자의 오픈소스 라이선스는 '더 보기'가 아니라 그 안의 '내 정보'에 둔다. 규칙 8.16이 이 행을 계정 메뉴에 두기 때문이다.

### 2. 화면 뼈대

767px 이하(휴대폰)

- 1차 화면(각 탭의 첫 화면) 아래에 탭바를 고정한다.
  - 높이 56에 `env(safe-area-inset-bottom, 0px)`를 더한다. 칸 안은 위에서부터 5·아이콘 24·5·라벨(`tab`, 줄 높이 17)·5다.
  - 칸은 같은 너비이고 칸 전체가 링크다. 바탕 `surface`, 위쪽 선 `border` 1px, 그림자 없음.
  - 기본 탭은 선 아이콘과 `text-secondary`다. 선택된 탭은 채운 아이콘, `primary`, 라벨 굵기 600이다. 바뀔 때 움직임은 없다.
  - 글자를 키우면 높이도 함께 늘고 라벨을 자르지 않는다.
- 1차 화면 내용 아래에 탭바 높이만큼 여백을 둔다. 스크롤 영역의 `scroll-padding-bottom`은 탭바 높이 + 20px이다.
- 하위 화면(요청 상세, '더 보기'·'내 정보'의 행 화면)에는 탭바가 없다. 위쪽에 뒤로 버튼(`chevron-left` 24, 누르는 영역 50×50, 이름 "뒤로")과 화면 제목을 둔다.
- 휴대폰의 위쪽 `작업 이동` 메뉴, 소속 선택, 로그아웃 줄은 없어진다. 40px 예외도 함께 없앤다(아래 PR 1 목록).

768px 이상

- 왼쪽 메뉴 248px. 지금은 1024px부터라, 768–1023px도 이번에 맞춘다.
  - 항목은 높이 50, 아이콘 20, 아이콘과 라벨 사이 5, 라벨 `body`다.
  - 현재 위치는 채운 아이콘, 굵기 600, `fill-hover` 바탕이다. 지금의 밑줄과 `fill-selected` 바탕은 쓰지 않는다.
  - 관리자는 '더 보기' 칸 없이 그 안의 1–3행(호실 정비 이력, 입주 연결, 건물·호실 관리)을 탭 항목 아래에 같은 순서로 펼친다(8.10). 이 세 항목의 아이콘은 결정 D9에서 정한다.
  - 맨 아래 계정 영역: 위쪽 `border` 1px 선, 현재 소속·역할 이름(`caption`, `text-secondary`, 위아래 10px), 그 아래 '내 정보' 항목. 개발 모드는 소속 대신 역할 이름만 쓴다.
- 하위 화면을 열어도 왼쪽 메뉴는 그대로다. 내용 영역 위쪽에 뒤로 버튼이 나온다.
- 관리자의 넓은 화면 업무함은 지금처럼 목록과 상세를 나란히 보인다. 상세를 열어도 목록이 남는다.

모든 폭

- 메뉴는 `<nav aria-label="주 메뉴">` 안의 링크다. 현재 위치에 `aria-current="page"`를 붙인다(12절).
- 탭은 숨기거나 비활성화하지 않는다. 저장 중에도 누를 수 있고, 진행 중인 요청은 화면 뒤에서 계속된다.
- 소속을 고르기 전 상태(불러오는 중, 로그인, 연결 확인 실패, 로그아웃 중, 소속 없음, 소속 미선택)는 지금 화면을 그대로 쓴다. 역할이 아직 없어서 메뉴를 그릴 수 없기 때문이다.
- 맨 아래 검증용 환경 안내(`EnvironmentNote`)는 내용 맨 끝, 탭바 여백 위에 남는다.

### 3. 주소와 뒤로 가기

- 주소는 `/core?tab=<탭>&view=<행 화면>`이다. 둘 다 1절 표의 값만 받는다.
  - `tab`이 없거나, 모르는 값이거나, 다른 역할의 값이면 그 역할의 첫 탭(세입자 `home`, 관리자 `work`)으로 바꾼다. 오류는 보이지 않고 `history.replaceState`로 주소를 고친다.
  - `view`가 그 탭에 속하지 않거나 그 역할에 보이지 않는 행이면 `view`를 지운다.
- 탭을 누르면 `history.pushState`로 기록을 남긴다. 그래서 브라우저 뒤로 가기가 탭 사이에서도 동작한다.
- 선택된 탭을 다시 누르면 그 탭의 첫 화면 맨 위로 간다. 열려 있던 하위 화면은 닫힌다(8.14).
- 요청 상세는 주소에 넣지 않는다. 열 때 같은 주소로 기록 하나를 남긴다(`history.state`에 상세 표시만).
  - 브라우저 뒤로 가기(`popstate`)는 상세를 닫고 들어오기 전 탭으로 돌아간다.
  - 미전송 사진이 있으면 지금 '목록으로' 버튼처럼 닫지 않는다. 기록을 다시 넣고 기존 안내 "목록으로 돌아가기 전에 미전송 사진을 저장하거나 선택 취소해 주세요."를 보인다.
  - 새로고침하면 그 탭의 첫 화면이 나온다(상세 딥 링크는 범위 밖).
- 화면의 뒤로 버튼은 이 페이지 안에서 연 하위 화면이면 `history.back()`, 주소로 바로 들어온 행 화면이면 부모 화면으로 `replaceState` 한다.
- 소속을 바꾸면 그 역할의 첫 탭으로 간다(8.16). 지금처럼 화면 상태는 소속마다 새로 만든다(`key`).

### 4. 탭 내용

세입자

- 우리 집(위에서부터)
  1. 결과 확인 이어하기 안내(지금의 `OutcomeRecoveryPanel`, 있을 때만).
  2. 처리할 일이 있으면 한 줄 "처리할 일 N건 · 알림에서 보기"(알림 탭 링크).
  3. 호실 이름과 건물 이름. 호실이 여럿이면 고르는 칸.
  4. 진행 중 요청 카드 최대 3개(완료 전 요청, 처리할 일 순서 → 최근 활동 순).
     - 카드: 요청 이름(문제 · 호실), 지금 상태 표시(기존 배지), 다음 할 일 한 줄, 보조 버튼 "열기".
     - 4개 이상이면 "내 요청에서 모두 보기" 링크.
     - 다음 할 일 문구는 순수 함수 하나가 정한다. 처리할 일 이유가 있으면 그 이유, 없으면 "관리자가 확인하고 있어요."(접수됨) 또는 "처리 중이에요."(처리 중)다. 문구는 해요체이고 10절을 따른다.
  5. 접수 칸 "어떤 문제가 있나요?"(지금 그대로, 주요 버튼 "접수하기").
- 내 요청: 지금의 '최근 접수' 목록을 옮긴다.
  - '진행 중'과 '끝난 요청'(처리 완료) 두 묶음으로 나눈다. 행 모양은 지금 그대로다(대화 표시 포함).
  - 우리 집과 같은 호실 선택을 쓴다.
  - 행을 누르면 상세(하위 화면)가 열린다.
- 알림: 처리할 일 목록(5절). 모든 호실의 요청을 보고, 행마다 호실 이름을 쓴다.
- 내 정보: 1절의 '내 정보' 목록.

관리자

- 업무함: 지금 업무함 그대로다. 화면 안의 `관리자 보기` 전환 버튼만 없앤다(호실 정비 이력은 '더 보기'로 옮김).
- 알림: 처리할 일 목록(5절).
- 더 보기: 1절의 '더 보기' 목록. 휴대폰에서는 목록 행(8.5)이고, 넓은 화면에서는 왼쪽 메뉴에 펼쳐져 있어 이 탭 화면을 따로 보이지 않는다(주소 `tab=more`만 오면 첫 행 화면 대신 목록을 보인다).

빈 화면(8.11)

| 화면 | 문구 |
| --- | --- |
| 세입자 알림 | 지금 처리할 일이 없어요. 새 문제가 생기면 우리 집에서 접수해 주세요. |
| 관리자 알림 | 지금 처리할 일이 없어요. 새 요청은 업무함에 들어와요. |

| 내 요청 끝난 요청 | 끝난 요청이 없어요. |

### 5. 처리할 일

순수 함수 하나(`todo-list.ts`)가 이미 불러온 데이터로 목록을 만든다. 서버를 직접 부르지 않는다. 결과는 행마다 "어느 요청(또는 연결 요청)인지, 이유 목록, 누르면 열 곳"이다.

| 이유 | 대상 | 조건 | 데이터 | PR |
| --- | --- | --- | --- | --- |
| 내 답변 필요 | 세입자 | 대화 요약 `waitingFor = TENANT`, `readOnly = false` | 대화 요약 일괄 조회 | 1 |
| 제출 전 | 세입자 | `isIntakeDraft` | 요청 목록 | 1 |

- 이유 이름은 화면의 기존 상태 이름과 같다(8.7, P3 이름 표). '제출 전'은 관리자 알림에 넣지 않는다. 세입자 차례이기 때문이다.
- 한 요청에 이유가 여럿이면 한 행에 모두 쓴다. 배지는 행 수를 센다.

- 읽는 시점: 요청 목록을 불러온 직후, 저장 같은 변경 뒤, 새로고침, 알림 탭을 열 때. 주기적으로 다시 읽지 않는다.
- 읽는 양의 한도
  - 대화 요약은 처리 완료 전 요청만, 50개씩 묶어 읽는다(서버 한도 50).
  - 요청마다 읽는 것(PR 2)은 처리 완료 전 요청(업체 일정·업체 전달)과 최근 끝난 요청 20건(결과)만, 동시에 4개까지다. 화면에 "최근 끝난 요청 20건만 확인해요"를 적는다.
- 일부를 읽지 못하면
  - 읽은 것만 보이고, 위에 "일부를 확인하지 못했어요"와 "다시 불러오기" 버튼을 둔다.

  - 401·403은 지금의 다시 로그인 흐름(`onDenied`)으로 보낸다.
- 누르면
  - 요청은 상세(하위 화면)를 연다. 상세 맨 위의 '지금 할 일'이 그 일을 보여 준다.
  - 연결 요청은 '더 보기 › 입주 연결'을 연다.

  - 알림 탭에만 있다. 0건이면 없고, 99건을 넘으면 `99+`다.
  - 높이 18, 최소 너비 18, 좌우 안쪽 5, 모서리 5, 바탕 `badge`, 글자 `text-inverse`, `tab` 600 `tabular-nums`.

### 6. 화면 상태 유지

- 탭과 행 화면은 지금처럼 모두 그려 두고 `hidden`으로 감춘다. 그래서 탭을 옮겨도 접수 칸에 쓴 글과 고른 사진이 남는다.

- 선 굵기는 1.5(규칙 8.13, Tabler 기본 2를 바꿈), 색은 `currentColor`, 장식용이라 `aria-hidden`이다.

## 남은 위험

- 기존 화면 시험 14개 파일이 바뀐다. 고정(FROZEN)된 화면을 바꾸므로 `ops/`에 이번 변경의 수락 기록을 새로 남긴다.
- 탭바가 화면 아래 56px를 가린다. 여백과 `scroll-padding-bottom`으로 막고 시험으로 확인한다.
- 휴대폰에서 입력 중 키보드가 올라올 때 탭바 위치는 브라우저마다 다르다(iOS Safari는 키보드 뒤에 남고, 안드로이드 크롬은 키보드 위로 올라올 수 있다). 자동 시험으로는 키보드를 띄울 수 없어 실제 기기로 확인한다. 접수 칸이 가리면 운영자에게 묻고 정한다.
- 안전 영역: 지금 화면 설정(`viewport-fit` 없음)에서는 iOS Safari의 안전 영역 값이 0이다. `env()`에 기본값 0을 주어 어느 쪽이든 맞게 한다. 앱처럼 화면 끝까지 쓰는 설정은 이번에 바꾸지 않는다.
- PR 2의 요청마다 읽기는 요청이 많은 조직에서 알림 탭을 늦게 채운다. 한도와 동시 4개로 묶고, 읽은 것부터 보인다.
- 관리자 대화 요약: HTTP 경로는 역할을 가리지 않지만, 지금 화면은 세입자에게만 이 요약을 읽힌다. PR 1의 첫 시험에서 관리자 세션으로 자기 조직 요청의 요약을 읽는지 확인한다. 안 되면 '관리자 답변 대기'를 PR 2로 미루고 운영자에게 알린다.
- `/workspace`는 옛 디자인이다. 메뉴에서 그 화면으로 가면 모양이 갑자기 바뀐다. 16절에 남아 있는 항목이다.
- 2-b6 세션이 `join-screen.tsx`와 `core-login-e2e/design.spec.ts` 한 줄을 고치고 있다. 코드를 고치기 전에 알린다.
- 모바일 앱은 여전히 탭바가 없다. 웹과 앱의 1차 메뉴가 같아야 한다는 13절은 앱 v2 때 맞춘다.
