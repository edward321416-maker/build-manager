## 문제

- Expo가 2026-10-12 14:25–14:31 UTC에 SDK 57 패치판을 냈습니다.
- CI `mobile-health`는 고정한 Expo Doctor 1.20.4를 돌립니다. Doctor는 Expo 서버에 있는 "SDK 57이 기대하는 버전"과 설치된 버전을 비교합니다.
- 그래서 저장소가 바뀌지 않았는데도 모든 PR에서 이 검사가 실패합니다. main `f5ff1ce`는 14:37 UTC에 통과했고, #128은 15:31 UTC에 실패했습니다.
- 규칙상 정확한 head에서 CI가 통과해야 병합할 수 있습니다(DEV-06). 그래서 #128과 다른 세션의 #129가 막혀 있습니다.

## 바꾸는 것

- 개발 규칙 DEV-10대로 `apps/mobile`에서 `npx expo install --fix`로 맞춥니다.
  - expo `~57.0.28`, @expo/ui `~57.0.23`, expo-router `~57.0.26`, expo-splash-screen `~57.0.10`
  - jest-expo는 지금처럼 정확한 버전으로 고정합니다: `57.0.6`. `expo install`은 `~57.0.6`으로 썼지만 원래 고정 방식을 지킵니다.
  - `expo install`이 `app.json`에 자동으로 더한 `expo-splash-screen` 설정 플러그인은 되돌렸습니다. 앱 빌드 설정이 바뀌는 일이라 이 작업 범위 밖입니다.
- react-native-web을 0.21.2에서 0.21.4로 올립니다. Babel 플러그인(babel-plugin-react-native-web)이 0.21.4로 올라가는데 짝인 react-native-web이 0.21.2에 남으면, 웹 번들에서 `AssetRegistry`를 찾지 못할 수 있습니다(끝 리뷰 지적).
- 잠금 파일은 CI와 같은 npm 11.19.0으로 씁니다. 바뀌는 항목은 26개이고, 새로 생기거나 없어지는 항목은 없습니다.
- AC17
  - `tests/architecture/expo-sdk57-patch-20261013-lock.json`에 26개 항목의 이전 값과 새 값의 해시를 담습니다.
  - 시험은 검토 기록을 최신 것부터 되돌린 뒤 원래 고정 해시와 비교합니다.
  - `apps/mobile/package.json`은 바뀐 다섯 줄만 원래 글자로 되돌려 원래 해시와 비교합니다. 글자 단위로 비교하므로 줄 바꿈·띄어쓰기·중복 키도 잡습니다.

- CI에서 Expo Doctor를 `EXPO_OFFLINE=1`로 돌리면, 잠금 파일에 든 Expo의 기대 버전과 비교하므로 바깥 패치판 때문에 CI가 실패하지 않습니다(끝 리뷰 제안). 다만 워크플로도 AC17 고정 대상이고, 새 패치판 소식을 놓치게 됩니다. 운영자 결정이 필요한 별도 작업으로 남깁니다.
